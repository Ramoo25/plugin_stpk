  скелет → окно (2 списка + «Закрыть») → реальные листы с натуральной сортировкой →

## 1. Цель

Плагин на Python (pyRevit) для Revit 2022:

1. Пользователь нажимает кнопку на вкладке ленты Revit.
2. Открывается окно со списком всех листов текущего проекта.
3. Клик по листу → под ним (в соседнем списке) появляется перечень видов, размещённых на этом листе (наименования видов).
4. Кнопка «Закрыть» закрывает окно.

Плагин **только читает** модель, ничего не изменяет → транзакции не нужны.

## 2. Окружение (уже проверено на этой машине)

- Revit 2022 (22.0.2.392).
- pyRevit 4.8.15, CLI `pyrevit` в PATH.
- Движок: IronPython 2.7 (дефолтный). **`pyrevit.forms` в pyRevit 4.8.15 недоступен под CPython** —
  скрипты с окнами всегда идут в IronPython (не ставить `#! python3` в первой строке).
- Расширения ищутся в добавленном через `pyrevit extensions paths` каталоге.

## 4. Логика

### script.py

- Движок — IronPython 2.7 (без `#! python3`; `pyrevit.forms` под CPython не работает в 4.8.15:
  WPF-окна только IronPython). Синтаксис ограничений Python 2.7 — `format()`, без f-строк.
- Стартовая проверка: если `revit.doc` отсутствует — `forms.alert("Откройте проект Revit.", exitscript=True)`.
- Получение листов:
  ```python
  sheets = (DB.FilteredElementCollector(doc)
            .OfClass(DB.ViewSheet)
            .WhereElementIsNotElementType()
            .ToElements())
  ```
- Индексация листов (кэш `Id → лист`):
  - отображаемое имя: номер листа + название (`SHEET_NUMBER`, `SHEET_NAME` — только через `BuiltInParameter`, никаких локализованных имён);
  - сортировка по номеру листа.
- Получение видов выбранного листа (API 2022 проверен):
  ```python
  view_ids = sheet.GetAllPlacedViews()   # ICollection[ElementId]; спецификации не входят
  names = [doc.GetElement(i).Name for i in view_ids]
  ```
  - дополнительно: вид-спецификация (schedule) на листе не возвращается методом —
    в v1 не показываем, фиксируем как известное ограничение; в v2 при желании через
    `ScheduleSheetInstance.OwnerViewId`.
- `ElementId` в 2022 — int: `id.IntegerValue` как ключ кэша (свойство `.Value` появилось только в 2024).

### Окно (ui.xaml + класс формы)

Режим: **модальное окно (`ShowDialog`)** — выполняется в потоке Revit, поэтому безопасно
читать модель прямо в обработчике клика; `ExternalEvent` не требуется (чтение, не запись).

Раскладка:

```
┌────────────────────────────────────┐
│ Листы проекта                      │  ← заголовок / подпись
│ ┌────────────────────────────────┐ │
│ │ ListBox lst_sheets             │ │  ← листы (номер + имя), сразу ActiveView? нет: все листы
│ └────────────────────────────────┘ │
│ Виды на листе                      │
│ ┌────────────────────────────────┐ │
│ │ ListBox lst_views              │ │  ← наименования видов выбранного листа
│ └────────────────────────────────┘ │
│                       [ Закрыть ]  │  ← btn_close, IsCancel=True (Esc тоже закрывает)
└────────────────────────────────────┘
```

Правила XAML (pyRevit):
- без `x:Class`;
- каждый элемент, нужный из Python, с `x:Name`;
- `WindowStartupLocation="CenterOwner"`, `ShowInTaskbar="False"`;
- файл в UTF-8, русский текст прямо в базовом `ui.xaml`.

Обработчики (подключаются из Python, не из XAML):
- `MainWindow` → / `lst_sheets.SelectionChanged` → заполнить `lst_views` (сначала очистить; если видов нет — показать плейсхолдер «На листе нет видов»);
- `btn_close.Click` → `self.Close()`.

Элементы списка — не сырые строки, а лёгкий класс на `forms.Reactive`, если понадобится
двусторонняя привязка; для v1 достаточно `ItemsSource` из строк + `DisplayMemberPath`.

| 1 | Создать скелет расширения (папки + bundle.yaml) | Кнопка появляется на ленте |

## 8. Ограничения и возможное развитие (v2, не входит в объём)

- Спецификации (schedules) на листе не показываются `GetAllPlacedViews()` — можно добавить через `ScheduleSheetInstance.OwnerViewId`.
- Показывать имя вида подлиннике на листе (`TITLE ON SHEET`, параметр `VIEWER_TITLE_MARK`/`SHEET_NAME` вида) вместо `view.Name`.
- Поиск/фильтр по листам, дублирование клика выделением вида в проекте.
- Немодельное окно (`Show()`) + `ExternalEvent` — если появится интерактив с моделью.

## 9. Плагины-последователи

- **«Связанные виды»** — отложен (откл./удалён из расширения 2026-10-31):
  в Revit 2022 нет API настройки отображения связей в виде
  (GetLinkOverrides/SetLinkOverrides появятся только в Revit 2024) — полный
  функционал недостижим на 2022. Каркас удалён (`Views.panel`); если вернуться
  к нему на Revit 2024+ — вся проработка сохранена в git-истории плана
  и в тексте этого файла ниже (аръхив ниже).
- Новый плагин разрабатывается на базе этого (см. `plan.md` — основной план).

### Архив: проработка «Связанных видов» (2026-10-30, отложено)

- Сценарий: 4 списка (листы → сущности листа → связи → связанные планы),
  «Применить» (активна после выбора связанного вида) и «По основному виду».
- Ключевая находка: в Revit 2022 нет API настройки отображения связей в виде
  (`RevitLinkGraphicsSettings`, `View.GetLinkOverrides/SetLinkOverrides/
  RemoveLinkOverrides`) — появились в Revit 2024 (What's New 2024, §2.14).
  Проверено по RevitAPI.dll (отражение + поиск строк) и What's New.
- Доступно в 2022: навигация полностью (`RevitLinkType.GetLinkDocument()`,
  сбор `ViewPlan` связанного файла), скрыть/показать связь
  (`View.HideElement/UnhideElement`), обход через дубликат настроенного плана
  (`ViewPlan.Duplicate()` копирует настройки VG, включая режимы связей).
- Вариант решения, если вернуться на Revit 2024+: полный функционал —
  `SetLinkOverrides(linkId, settings)` c `LinkVisibility.ByLinkView` +
  `LinkedViewId` в транзакции; текущий режим показывать через
  `GetLinkOverrides`.
