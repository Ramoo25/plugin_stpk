### Функционал (согласовано, обновлено 31.10)
- Слева — строки по каждому загруженному семейству
  (`FilteredElementCollector.OfClass(Family)`): **чекбокс + имя +

- Справа — выбор для размещения: **связь** (если больше одной),

  с `symbol.Activate()`; неудачи перехватываются в отчёт
  («семейство X не размещено: причина»), остальные ставятся.

### Техминимум (проверка API 2022 при реализации)
- Помещения связи: `RevitLinkType.GetLinkDocument()` →
  collector `DB.Room` на нужном уровне связи (`LevelId`); контур:
  `room.GetBoundarySegments(SpatialElementBoundaryOptions)`;
  точка внутри: `room.Location.Point` (Link LocationPoint).
- Преобразование координат: `revitLinkInstance.GetTotalTransform().OfPoint(...)`.
- Точка в полигоне: алгоритм пересечения лучом (2D, в координатах хоста).
- Создание: `doc.Create.NewFamilyInstance(XYZ, symbol, hostLevel,

  перед первым использованием; полностью в одной транзакции.
- При случайных смещениях: повторные попытки (N=10) + fallback
  на точку метки помещения.
- Открыто: если связей несколько — где брать помещения (выбор связи,

## 1. Функционал (от пользователя)

Задача: **просматривать и по необходимости изменять** параметры листов
и размещённых на них видов. **Это первый плагин с ЗАПИСЬЮ в модель** —
потребуются транзакции.

Параметры в фокусе:

| Объект | Параметр (RU UI) | API-представление (2022, проверено) | Изменение |
|--------|------------------|--------------------------------------|-----------|
| Лист | «Номер листа» | `BuiltInParameter.SHEET_NUMBER` (ViewSheet) | ✏️ да |
| Лист | «Имя листа» | `BuiltInParameter.SHEET_NAME` (ViewSheet) | ✏️ да |
| Вид (размещённый) | «Заголовок на листе» | `BuiltInParameter.VIEW_DESCRIPTION` («Title on Sheet») | ✏️ да |
| **Лист** | «ADSK_Штамп титульный_Наименование документа» | shared-параметр, поиск по имени строки (`sheet.LookupParameter(...)`); **живёт на листе — подтверждено пользователем 31.10** | ✏️ да |

Сценарий (зафиксирован 31.10 вместе с интерфейсом):
1. Кнопка на вкладке «ПлагИН» → окно.
2. Вверху-слева — список листов («номер - имя» одной строкой).
   Выбор листа → его поля (Номер, Имя, ADSK-наименование) переносятся
   в редактируемые текстовые поля справа, под ними кнопка **«Сохранить»**;
   параллельно внизу-слева заполняется список **видов, размещённых
   на выбранном листе**.
3. Выбор вида → его «Имя вида» и «Заголовок на листе» переносятся
   в редактируемые поля справа, под ними кнопка **«Сохранить»**.
4. «Сохранить» (лист) — записывает параметры листа в транзакции;
   «Сохранить» (вид) — записывает параметры вида в транзакции;
   после записи кэш и списки обновляются, выделение сохраняется.
5. «Закрыть» — закрыть окно (Esc).

## 2. Классификация изменений (запись в модель!)

- Изменённые поля — **в транзакции**; окно остаётся модальным
  (`ShowDialog`, как v1.0) — транзакция из обработчика допустима.
- Шаблон записи (pyRevit 4.8, проверено по исходникам установленной
  библиотеки `pyrevitlib\pyrevit\revit\db\transaction.py` — это
  обёртка-контекстный менеджер над `DB.Transaction`):
  ```python
  with revit.Transaction(u"ПлагИН: правка параметров листа", doc):
      param.Set(new_value)
  ```
  (автоматически Start/Commit, при исключении — Rollback).
- До записи: валидация (не пустое значение для номера листа и пр.).
- После записи: обновить кэш и UI (как минимум видимые поля);
  Undo-стек пользователя растёт на одну операцию на «Сохранить» — это
  нормально, уведомлять не нужно.
- Ловушки:
  - `SHEET_NUMBER`: дубликаты номеров Revit не запрещает — не запрещаем и мы,
    но подсветить/сообщить о совпадении при сохранении;
  - ADSK-параметр: если у элемента его нет (`LookupParameter` → None) —
    поле без редактирования + подпись «(параметра нет)»;
  - «Заголовок на листе» (`VIEW_DESCRIPTION`) реально живёт на **View**,
    а не на viewport — собирать от `doc.GetElement(view_id)`;
  - исключения WPF-обработчиков — в лог через `script.get_logger()`
    (гаснут тихо — урок v1.0).

┌───────────────────────────┬──────────────────────────────┐

│ ┌───────────────────────┐ │   Имя вида      [======][..] │

│ │ СП Ведомость…        │ │   [ Сохранить ]              │

## 10. Плагин №4 «Масштаб видов» (`Scale.panel\ViewScale.pushbutton`)

Статус: ✅ **работает (подтверждено пользователем 01.11)**.
Отлажено: запись масштаба через параметр `VIEW_SCALE` падает
("The parameter is read only") - масштаб пишется **свойством
`View.Scale`** (док 2022). Тот же дефект найден и исправлен в
плагине №2 (правка масштаба вида через «Сохранить»); подтверждено.

### Функционал (согласовано 01.11)
- Иерархическое дерево слева: уровень 1 — листы проекта, подпись
  «номер - имя» как в плагине №2; уровень 2 — виды, размещённые на
  листе (`GetAllPlacedViews`), **без легенд и спецификаций** — только
  виды. Лист — просто заголовок группы (без чекбокса), развёрнут.
- Чекбоксы у видов (пометка «что меняем»); «Отмечено видов: N».
  Вид размещается ровно на одном листе (порт-вид, Revit 2022) - поэтому
  дубли по Id не случаются; фильтр по Id в коде оставлен как защита.
- Справа: один общий ввод масштаба — редактируемый ComboBox со
  стандартным рядом («1:100» и т.п.), вводится и число («100»), и «1:100»;
  парсинг: всё после «:».
- «Применить»: транзакция «ПлагИН: масштаб видов»,
  параметр `VIEW_SCALE` (`view.get_Parameter`), проверка
  `IsValidViewScale`; виды, у которых масштаб уже равен — в счёт «уже
  был»; отказы (placeholder-виды и пр.) — в отчёт построчно.
- «Очистить выбор» — кнопка (снятие всех галочек).
- **Чекбокс у листа НЕ делаем** (решено 01.11).

### Техминимум
- Отбор видов: `isinstance(view, ViewSchedule|ViewLegend)` → skip.
- Масштаб: `BP_VIEW_SCALE`, диапазон 1-24000 (проверка `IsValidViewScale`
  дублируется диапазоном - при отсутствии видов-параметров).
- Сбор листов - по образцу плагина №2 (`element_name_safe`,
  `sheet_number_safe` с фолбэком на BP).
- Доработки 02.11: строка поиска над деревом (динамический фильтр:
  совпало имя листа - показаны все его виды; совпало имя вида -
  виден только вид; лист без совпадений скрыт) + чекбокс «Только
  выбранные» (текст игнорируется, поле поиска гаснет, в дереве остаются
  только отмеченные виды; снятая галочка сразу скрывает вид; «Очистить
  выбор» отрабатывает и видимость). Фильтрация меняет только видимость
  узлов - отметки и развёрнутость дерева сохраняются.
- Доработки 03.11: подписи у полей - «Содержит:» (прежний фильтр)
  и новая строка «НЕ содержит:» (tb_exclude) -
  листы/виды, содержащие текст исключения, скрываются (лист с текстом
  исключения скрыт целиком); в режиме «Только выбранные» оба поля
  гаснут и игнорируются.
- Доработки 03.11б: слова в поля вводятся через запятую: «Содержит» -
  остаётся всё, где встречается ХОТЯ БЫ ОДНО из слов (ищем и в листах,
  и в видах); «НЕ содержит» - исключается всё, где встречается хоть
  одно из слов.
